# ADR-0001: Qi 可视化 dashboard 采用静态快照（本地网页，非 DSH 插件）

日期：2026-11-21
状态：已接受（grilling 两轮 11 问，用户确认）

## 背景

用户想要「Qi 的工作面板，可视化」，最初设想做成 DeepSeek Harness（DSH）插件。
经第一性原理拷问（grilling），真实诉求是 B：**只要一个能看清资产的可视化 dashboard，载体不重要**。
DSH 插件路线被否决：面板形态受 slot 机制约束、替换已装包需重启、client 热更新依赖 `pnpm run dev:web` 构建链——对一个"低频查看的配置中心"是重装备。

## 决策

1. **形态**：静态快照。`tools/build-dashboard.py`（Python 标准库单文件，零第三方依赖）
   扫描仓库 → 数据内嵌生成仓库根 `dashboard.html`，双击即开（`file://` 即可，无服务无依赖）。
2. **数据源**：仅 Qi 仓库本身，不读本机 `~/.dsh`、`~/.agents` 等安装态。
   八板块：自研 skills（`skills/` 目录）｜第三方 skills（`third-party.md`）｜
   自研 plugins（`plugins/` 目录）｜第三方 plugins（`plugins/third-party.md`）｜
   prompts（`prompts/`）｜核心提示词（`global/AGENTS.md`）｜MCP 服务器（`mcp/mcp.template.json`）｜当前规划（`tasks/todo.md`）。
   顶部统计条：各类总数 + 仓库最近变更。
3. **健康度 = 时间视角，无红绿灯**：每条目/每类别展示 git 最后变更距今天数。
   不做"久未变动=不健康"的规则判断（对 prompts 稳定是好事，对第三方才中性）；
   上游版本核对是《月度更新流程》的职责，dashboard 不联网、不越界。
4. **刷新**：手动重跑脚本为兜底；《月度更新流程》末尾顺带重生成（写入 SETUP.md）。
   不用 git hook（本机状态，换机丢失，且不提交的改动照样让快照过期）。
5. **生成物不入库**：`dashboard.html` 进 `.gitignore`，git status 保持干净，随取随生成。
6. **视觉与交互**（2026-11-24 更新）。沿用 KARLO 纸墨色系并随系统切换明暗。
   首屏用一条按真实数量分段的比例条呈现四类资产，核心提示词计入提示词，规划待办单独计数。
   桌面用吸顶侧栏跳转，窄屏用顶部吸顶目录。跳转会展开目标章节，滚动时更新当前位置。
   清单默认收起，支持展开或收起全部，并在浏览器存储可用时记住折叠状态。
   描述直接换行展示，窄屏将表格条目纵向排列。脚本禁用时默认展示全部清单。
   常用提示词复制分隔线以下的正文，核心提示词可预览并复制母版全文。
   复制优先用 Clipboard API，保留旧式复制回退。外部来源在新标签打开。
   页面字体取自本机，首次打开也可离线加载。

## 理由

- 快照模型与 Qi 的本质对齐：Qi 是**人工策展的档案库**（目录即清单、进货单即清单），
  变更频率 = 人的收录频率，低频；实时性没有信息价值。
- 仓库内可观测的"健康"只有时间和记录两种事实；替人下判断的红绿灯规则，
  错了比没有更糟。等看了一段时间真实数据再决定要不要灯。
- Python 标准库：仓库无 Node 工具链，DSH 环境自带 Python，脚本零依赖可移植。

## 后果

- 正面：双击即看、零常驻成本、脚本可读可改、验收明确
  （双击 `dashboard.html`，30 秒内看清各类资产及时间状态，不翻文件夹）。
- 负面/接受：快照必然滞后于仓库真实状态（缓解：月度重生成 + 手动兜底）；
  进货单是给人读的自由格式 markdown，解析器需跟随格式演进（解析规则见脚本头部注释，
  格式大改时脚本同步改）。

## 备选方案

- **DSH 插件面板**：否决，见背景。若未来诉求变为"聊天时常驻入口"或"学习插件机制"，可重开。
- **常驻本地服务（watch 实时）**：否决，常驻进程 + 端口管理对低频查看是重装备。
- **生成物入库**：否决，每次重生成都是待提交变更，污染 git status。
